# AccaForge UI/UX Review Checklist

## Product truth
- [ ] Edition rules and labels are preserved.
- [ ] No guaranteed-win, risk-free, or urgency language.
- [ ] Estimated and bookmaker-implied probabilities remain distinct.
- [ ] PASS is presented as a legitimate research outcome.
- [ ] 18+ and responsible-play information remains accessible.

## UX and visual quality
- [ ] Page purpose and primary action are clear.
- [ ] Fixture, market, selection, price, bookmaker, and kick-off time scan quickly.
- [ ] Information hierarchy survives 320 px mobile width.
- [ ] Long names and large numeric values do not clip.
- [ ] Shared components use semantic design tokens.
- [ ] Loading, empty, error, and unavailable states are designed.

## Accessibility
- [ ] Keyboard navigation and visible focus.
- [ ] Semantic headings, landmarks, links, buttons, and labels.
- [ ] Contrast and text zoom/reflow.
- [ ] Status is not communicated by color alone.
- [ ] Reduced motion and touch targets.

## Engineering verification
- [ ] TypeScript check and production build.
- [ ] Browser review of desktop/mobile routes, if available.
- [ ] No unrequested business-logic changes.
- [ ] Report only verification actually performed.
